# Sourcemap-style AAI dashboard — design spec

Date: 2026-09-15
Status: approved by Janak in chat, pending final spec review before implementation

## Why

Janak wants his AAI JE (Operations) CBT study dashboard restructured around the sourcemap.co
model: a fixed-length, day-by-day program with one objective per day, a 5-criteria mastery
rating per day, a spaced-repetition queue for weak days, and a visual "wall" of progress —
instead of the current flat concept-table structure. He shared a screenshot of Sourcemap's
actual logged-in app (sidebar nav, gradient day-progress bar, dark hero day page, pentagon
mastery wall) and wants that exact shell, with all of his dashboard's existing tabs folded in
underneath it rather than removed.

## Assumed exam date — IMPORTANT CAVEAT

AAI has **not** officially announced the Advt 12/2026/CHQ/DR-CBT exam date as of 2026-09-15.
Web search found aggregator sites (testbook, adda247, etc.) guessing "expected mid-October
2026" — unverified. **Janak explicitly chose to assume 19 November 2026** as the working exam
date for this schedule (his call, made knowingly against the unverified mid-Oct guess). This
gives a working runway of 65 days from 2026-09-15.

This assumption must be:
- Displayed clearly in the UI (e.g. "Exam date: 19 Nov 2026 (assumed, not yet officially
  announced by AAI)") — never presented as confirmed fact.
- Re-checked periodically (the existing GK_CURRICULUM.md / AAI.aero recruitment dashboard
  monitoring habit already covers this — extend it to include the exam-date announcement).
- Easy to re-anchor: the day-sequencing algorithm (below) must take the exam date as a single
  config value, not something hardcoded across multiple files, so the whole calendar can shift
  in one edit if AAI announces a different date.

## Scope

**Replaces**: the dashboard's default landing experience and primary navigation model.
**Preserves unchanged**: `QUESTION_BANK.md`, `STUDY_PROGRESS.md`, `ERROR_BOOK.md`,
`MOCK_RESULTS.md`, `GK_CURRICULUM.md` as the source of truth; the live-teaching-in-chat
workflow; `build.py`'s existing parsing of those files; the public GitHub Pages deployment
flow (rebuild → commit → push → Actions).
**Adds**: a day-sequencing pass in `build.py`, a `days` array in `data.json`, new UI
components and pages, new nav items — additive to the existing `NavGroup`/`NavItem` system in
`shell.tsx`, not a replacement of it.

## Data model

New `days` array in `data.json`, generated by a new function in `build.py`:

```
{
  number: int,                 // 1-indexed, sequential
  phase: str,                  // "Part-A General" | "Physics" | "Maths" | "Aviation"
                                // | "Business Mgmt" | "Consolidation/Mock"
  title: str,
  objective: str,               // one testable sentence
  concept_ids: [str],           // links into existing STUDY_PROGRESS.md concept rows
  question_ids: [int],          // linked QUESTION_BANK.md Q-numbers (exercise + recall)
  mastery: {
    explain: "unrated" | "pass" | "fail",
    recall: "unrated" | "pass" | "fail",
    apply: "unrated" | "pass" | "fail",
    spot_trap: "unrated" | "pass" | "fail",
    speed: "unrated" | "pass" | "fail"
  },
  status: "not_started" | "in_progress" | "done",   // done = all 5 mastery criteria pass
  scheduled_date: "YYYY-MM-DD"  // computed backward from the assumed exam date
}
```

### Day-sequencing algorithm

1. Read every concept row across all subject tables in `STUDY_PROGRESS.md`.
2. Group by subject block matching the official mark-map: Part-A General (~40% of days),
   Physics (~20%), Maths (~20%), Aviation (~10%), Business Mgmt (~10%).
3. Within each subject, preserve the order concepts were actually taught/introduced
   (dependency order — e.g. differentiation before integration), falling back to the order
   they appear in the file for concepts not yet taught.
4. Concepts already **Solid or Mastered**: compressed into shared revision days (several per
   day), not given a full fresh day — they don't need re-teaching, just spaced review.
5. Concepts **Learning, Weak, or Not started**: each gets its own full day.
6. Reserve the final ~15 days as `Consolidation/Mock` phase: sectional tests building to full
   120-question timed mocks, per the existing CBT-and-mock-rules section of `AAI/CLAUDE.md`.
7. Assign `scheduled_date` by walking backward from the assumed exam date (19 Nov 2026),
   skipping a configurable rest-day cadence (default: none skipped initially — every day is a
   study day, matching Sourcemap's every-day cadence; revisit if Janak wants rest days).

### Mastery wedges (adapted from Sourcemap's Explain/Recognize/Apply/Debug/Tradeoffs)

Five criteria, confirmed in chat:
- **Explain** — say the concept back in his own words
- **Recall** — answer a question on it cold, no hints
- **Apply** — solve a fresh modelled question correctly
- **Spot-the-trap** — correctly identify the specific trick/trap that catches wrong answers
  (this is AAI's replacement for Sourcemap's "Debug," since there's no code to debug here —
  it's the direct MCQ-prep analogue: recognizing *why* a distractor is wrong)
- **Speed** — answer within CBT pace (~60 seconds/question average, from the 120Q/120min format)

A day is only `status: done` when all 5 are `pass` — no partial-credit "mastered" state,
matching Sourcemap's rule and Janak's own standard for honest progress tracking.

Ratings are recorded by me (Claude) during live teaching sessions in chat, written into a new
compact per-day block in `STUDY_PROGRESS.md`, and flow into `data.json` on rebuild. No new UI
for self-rating is being built in this phase — Janak doesn't self-rate via clicking, I rate
based on what he demonstrates in the conversation, consistent with how teaching already works
in this folder.

### Spaced-repetition queue

Reuses Sourcemap's rung system directly:
- A day with any `fail` criterion re-enters review at widening intervals: 1 → 3 → 7 → 14 → 30
  days.
- Correct on a scheduled review → moves to the next rung out.
- Missed → steps back one rung (never all the way to the start).
- Queue capped at **10 reviews/day** — prevents weak-topic debt from crowding out new-day
  content, same reasoning Sourcemap gives (uncapped it could reach ~30 by day 45).
- This directly formalizes what `STUDY_PROGRESS.md`'s "Next actions" section already does by
  hand (the BCAS/QNH-QFE/blood-relations overdue-redrill pattern) — replacing manual prose
  tracking with a real queue.

## Navigation

Extends the existing `NavGroup[]` array in `page.tsx` — no change to `shell.tsx`'s mechanism,
only its visual chrome (see Visual direction below) and a new pinned group at the top:

```
New group (unlabeled, pinned top): Today | Roadmap | Review | Progress
Existing groups, UNCHANGED:
  Overview: Mind Map | Everything | Syllabus coverage
  AAI exam: [per-subject pages] | Error book | Sessions and mocks | Question bank | GK | Mock test
  Lesson graphs: [existing graph/diagram pages]
  TOMORROW: Markets | AI consulting
```

`Today` becomes the new default landing section (replacing `Everything`/Overview as the
first-shown panel), everything else reachable exactly as it is today.

## Pages

**`Today`** — dark hero matching the shared screenshot: day badge ("DAY N OF 65"), phase +
progress line, large bold day title, objective paragraph, three stat items with time
estimates ("Learn it," "Practice it," "Recall and rate — 0 of 5 rated"), "Continue Day N"
pill button, "Tomorrow: ..." preview text pulled from day N+1's title.

**`Roadmap`** — phase-grouped day list: each phase as a section with day-count/hours badge,
numbered rows below (day number, title, one-line objective, status pill, mini 5-dot mastery
indicator). Clicking a day opens its detail (reuses the `Today`-style layout for any day, not
just the current one).

**`Review`** — due-today queue (capped at 10) from the spaced-rep rungs, plus a visible
"N reviews due today" indicator surfaced on `Roadmap` too.

**`Progress`** — "YOUR WALL": one pentagon per day (65 total), outline-only until all 5
wedges pass, then filled. "N of 65 marked" counter. Existing Overview charts (mastery rings,
status mix, cumulative sessions) move here, below the wall.

## Visual direction

Dark-first, minimal, typographic — matching the shared screenshot: near-black hero background,
large bold white headline text for day titles/objectives (stated as testable outcomes, not
vague topic names), generous whitespace, one restrained accent color (the existing `--brand`
CSS variable, not Sourcemap's coral — keep Janak's existing color identity, just adopt the
layout/typography/information-density language), small uppercase badge/pill labels for phase
and status, gradient day-progress bar in the sidebar, pentagon-shaped mastery indicators
(5 sides = 5 criteria, visually literal). No decorative clutter beyond what's shown in the
screenshot.

This is a deliberate style change for the `Today`/`Roadmap`/`Review`/`Progress` pages
specifically. Existing pages (subject lesson pages, error book, question bank, etc.) keep
their current styling unchanged in this phase — restyling those to match is a separate,
later decision, not bundled into this one.

## Out of scope for this pass

- Self-service mastery rating UI (clicking to rate yourself) — ratings stay Claude-driven
  during live teaching, consistent with current practice.
- Rest days / pace adjustment UI — default is every day is a study day; revisit if needed.
- Restyling the pre-existing detail pages (subjects, error book, question bank, GK, mock
  test, lesson graphs, markets, consulting) to match the new visual language — they keep
  their current look.
- Any change to the Reticle dev-tooling files sitting uncommitted in this repo — unrelated,
  explicitly left alone per Janak's decision earlier this session.

## Risks / open questions

- **Exam-date assumption drift**: if AAI announces a real date far from 19 Nov, the whole
  `scheduled_date` backward-walk needs re-running. Mitigated by keeping the exam date as a
  single config value (see algorithm step 7).
- **Day-count estimate (~65)**: actual count depends on how many concepts are genuinely
  Learning/Weak/Not-started vs compressible Solid/Mastered revision days once the algorithm
  actually runs against current `STUDY_PROGRESS.md` — the real number could land anywhere
  roughly 45-65 teaching days plus ~15 consolidation/mock days. This will be reported honestly
  once `build.py`'s new logic actually runs, not promised as exactly 65 in the UI copy.
- **ATC reference material (843 questions, Q248-843 banked 7-11 Sep)**: explicitly NOT
  included in the day-sequencing pass — those are reference-only, different-post material per
  `past_papers/README.md`, not part of Janak's actual Operations-post day-by-day schedule.
  Only Q1-247 (the two Operations-post papers already fully taught) and the underlying
  `STUDY_PROGRESS.md` concept tables feed the sequencer.
